## Why this slice

## In scope

TES3 `Morrowind.esm` + `Morrowind.bsa` + existing extra data folders. No new plugins.

- Parse top-level `PGRD` on the same ESM pass as `CELL` for **both** `loadInterior` and `loadExterior`. Do not parse it on `listInteriors` (CELL-only) or the objects-only `load`.
- Subrecords:
  - `NAME` — string (interior cell name; exteriors may be cell or region).
  - `DATA` — 12 bytes: `i32` gridX, `i32` gridY, `i16` granularity (keep, unused), `u16` point count.
  - `PGRP` — `pointCount` points, **16 bytes** each: `i32` x, y, z, `u8` autogenerated, `u8` connection count, 2 pad. Size must be `16 * pointCount` or skip the record (log, do not throw).
  - `PGRC` — `uint32` neighbor indexes. For each point in order, take `connectionCount` indexes; each makes an edge `v0 = pointIndex`, `v1 = neighbor`. Too few values → skip the record.
  - `DELE` — treat as empty (no grid).
- Empty points **or** empty edges: no grid for that cell (OpenMW erases; mods use this to delete). Do not keep a half record.
- After the ESM loop, attach to cells with OpenMW’s key (claim below): interior by cell **name** when `gridX == 0 && gridY == 0` and that name is an interior `CELL`; else by **DATA** grid. Collect interior names from `CELL` flags bit0 during the same pass so a `PGRD` that appears before its `CELL` still binds.
- Store on `LoadedCell` (interior / exterior center) and each exterior `GridTile`. Missing → 0 points. Stored TES xyz are **cell-local** (exteriors 0–8192 in that cell). Overlay adds `grid * 8192` for exteriors, then parents under the cell root so the same −90° X as land applies.
- Debug overlay: a blue sphere per node and cyan lines for edges, on at load, **F5** to hide. Water cameras skip it. Never `ModelBatch`.
- Wander, walk kf, and HUD buttons are unchanged. Class comment on the new pathgrid type and the overlay type (plain English, per AGENTS).
- Debug CLI:
  - `cell <name>`: one extra `pgrd=N e=M` on the header (or the next line).
  - `exterior x y`: each `grid=` line gets `pgrd=N e=M`.
  - New `pgrd <interior name>` and `pgrd <gridX> <gridY>`: header plus `node=i tes=x y z conn=k` and `edge=a b` for that one cell. Empty grid prints `pgrd=0 e=0` and no nodes.

## Other-LLM claims (held 2026-09-20)

1. Interior vs exterior key.

A PGRD record does not say if it is interior or exterior.
NAME is the interior cell name.
For exteriors NAME is the cell name, or the region if the cell has no name.
DATA mX and mY are 0,0 for interiors.
There is also an exterior cell at 0,0 so XY is not enough.
It is interior only if mX is 0, mY is 0, and Cell search of NAME hits an interior.
Cell search(string) looks in mInt then mDynamicInt only.
It does not look up exteriors by name or by grid.
The store key is NAME if interior, else esm3ExteriorCell of mX and mY.
Deleted, empty points, or empty edges erase that key.
A later non-empty record overwrites.
